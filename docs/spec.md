## 1. 概述

### 1.1 产品是什么

在 Windows 本机运行的 **多 Agent 沟通平台**：为多个开源/闭源大模型创造共享「聊天室」。用户提出问题或任务后，多个 Agent（各绑独立模型会话）在 **共享可见工作稿** 上协作——审阅、局部补丁、评判合入或打回——最终产出 **最终回复**；需要时再调用本机工具落地（写文件、跑脚本、生成表格/小游戏等）。

### 1.3 主交互范式（Chat Review v2）摘要

```
用户提问（未提问则房间空闲不运转）
  → 职责：评议模型 vs 工人模型（P0 默认双模型：非评议方=工人）
  → 工人：首答 → 将首答再喂回自身做静默检查
  → 无实质问题：等待「评议通过」→ 最终回复 / 可执行
  → 有实质问题：实质补丁 → 评议点合入 → 确认轮（仅可改 ChangedSet）
       → 确认轮仍有问题则再补丁再确认（封顶约束）
       → 确认轮干净后：等待「评议通过」→ 最终回复 / 可执行
  → （可选 P1+）用户点交付 / 执行补充 → 仍须曾获评议通过
```

**「通过」分层：** 静默检查通过 / 审阅沉默同意 / 合入 / 确认轮沉默 / **评议通过**——前几项都是**当前轮次、当前角色**的通过；唯有 **评议通过** 才打开最终回复与执行门禁（详见术语表）。

## 2. 术语表（含糊点显式定义）

| 术语 | 定义 |
|------|------|
| **用户原话 / 原话锚定** | 用户本轮提交的原始问题与约束文本；评判上下文必须包含且可引用；中间讨论不得静默改写该锚点 |
| **Agent** | 持久身份实体，绑定一个主模型（可有备用）；拥有独立会话句柄 |
| **模型** | 某 API 端点 + 模型 ID；「首答模型 ≠ 评判模型」按 **模型配置 ID** 比较，不是按显示名 |
| **共享工作稿 / 共享稿** | 房间内权威正文，带区块 ID 与版本号；**唯一**允许被 PATCH/合入/微调改写的协作正文 |
| **共享记忆** | 平台层键值/检索库：原话约束摘要、已通过终稿指针、待办、交付索引等；**不是**另一份可旁路改写的正文。通过前的过程稿不写入「已决议」 |
| 私有记忆 | 仅某 Agent 可见的草稿/中间推理；与**私有思考区**同层概念；不得进入他模上下文 |
| **区块 ID** | 稿内稳定片段标识（段落/列表项/代码块等）；补丁必填 `target` |
| **工人模型** | P0 默认：房间内非评议的那一个模型；负责首答、静默检查、补丁与确认轮响应；不得做评议通过 |
| **评议模型** | 负责点合入/合并/R1·R2·R3/**评议通过**；不参与过程闲聊；与首答模型不得为同一模型配置（降级 A 时用户代评议） |
| **私有思考区** | 每模型独立草稿/推理存储；**他模不可读**；自然语言可先落此区 |
| **白板** | 共享稿 + 房间事件总线；**模型间唯一合法交流通道**；不得直读他模私有思考/记忆 |
| **静默检查** | 首答入库后，工人模型将首答再输入自身做一轮自检；无实质问题则申报静默检查通过 |
| **轮次通过** | 某角色对**当前轮次**表态通过（如静默检查通过、确认轮沉默同意）；**不等于**任务结束 |
| **评议通过** | 仅评议（或用户）点击；表示当前共享稿可作为最终回复并允许执行；每条干净收敛路径上须点 **一次** |
| **已读** | Agent 对 **当前稿版本** 显式确认已阅读；发有效 PATCH 视为已读该版本 |
| **有效补丁** | 通过琐碎过滤器、字段完整、进入待合入队列的实质 PATCH |
| **无效贴** | 被系统拒收的琐碎/缺字段/超范围贴；**不**计入「有补丁」、不打断收敛 |
| **同意（沉默同意）** | 对该稿版本：**已读 ∧ 本轮无有效补丁**。超时未表态 **≠** 同意 |
| **弃权** | 显式声明不参与本轮审阅；**不**算同意，也 **不** 计入「有效审阅者」分母（见下） |
| **有效审阅者** | P0 默认即工人模型（含自审）。多审阅者非 P0 必做。评议者不计入分母。极端无人时确认轮以用户已读替代 |
| **自审 / 静默检查** | 工人将首答再喂回自身检查；可已读、可打实质 PATCH；**不可**评议通过 |
| **审阅窗** | 首答+静默检查之后，收集已读与有效补丁的时间窗（静默无问题则可很快进入等待评议通过） |
| **待合入队列** | 已受理、尚未被评议点合入的有效补丁集合 |
| **评议 / 评判** | 同义：评议模型职责；含合入、合并、R1/R2/R3、**评议通过** |
| **点合入** | 评议确认将补丁写入共享稿并递增版本 |
| **R1 / R2 / R3** | 局部打回 / 方向打回(A 旧稿作废) / 评判实现微调。见 M6 |
| **R1 关闭** | 被打回区块在「重交内容被评判点合入」后视为关闭；关闭时触发确认轮（+1） |
| **确认轮（+1）** | 合入 / R3 / R1 关闭合入后强制开启；本轮 **仅允许对 ChangedSet 内块** 打实质补丁；干净后须等 **评议通过** 才能 Final（禁止跳过确认轮） |
| **ChangedSet** | 触发本确认轮的写稿所改动的 blockId 集合（合入 target / 合并块 / R3 块 / R1 重交块） |
| **最终回复** | 评议通过后写入用户可见槽位的正式答案 |
| **资格锁** | 本轮已产生「首答」行为的模型配置 ID，不得再任本轮评议 |
| **降级 A** | 房间仅 1 个可用模型时，评议强制为用户 |
| **执行补充** | 可选子流程；须已获评议通过（或等价门禁）后方可正式执行/交付 |
| **房间事件总线** | 广播白板事件：稿版本、已读、有效补丁、拒收、裁定、工具回执；非点对点私信 |
| **房间空闲** | 用户未提问时不启动 Agent 流程；仅提问后唤醒 |

2. 要最终回复，不要琐碎润色刷屏。  
3. 分歧只改冲突块，评判点合入。  
4. 单模型时自己当评判，模型不能自行通过。  
5. （P1+）生成总结/文档并本机落盘。

### 5.3.1 「授权落盘」与「点交付」状态关系（P1a）

两者都可打开 **正式工作区写权限**，但入口不同：

```
                    ┌─ JudgeApprove 成功 ─► FinalCommitted
                    │                              │
用户提问 → … Review ┤                              ├─► 可「点交付」(T1) ─► M12 写盘 ─► ToolReceipt
                    │                              │
                    └─ 尚未 Final 时 ───────────────┴─► 用户可在评判台点「授权落盘」
                                                       （显式旁路：允许 M12，但仍须审计记授权）
```

| 状态/动作 | 前置 | 效果 |
|-----------|------|------|
| `FinalCommitted` | `JudgeApprove` | 最终回复槽有正文；**默认**允许点交付 |
| **点交付**（Deliver） | `FinalCommitted`（推荐）或有效「授权落盘」令牌 | 触发 M12 写入工作区 |
| **授权落盘**（AuthorizeWrite） | 用户在评判台确认；用于未 Final 但需紧急落盘，或 Final 后补授权 | 发放一次性/限时 `writeToken`；**不**自动等于已 Final |
| 无 Final 且无授权 | — | M12 拒绝写正式路径 |

**单一结论：** 「点交付」= 用户触发的 T1 落盘动作；「授权落盘」= 写权限令牌。正常路径是 Final → 点交付；授权落盘是例外旁路，须审计。

### 5.3.2 沟通前后工具钩子时机表（EX-01/02、J-06/07、D-05/06）

| 时机 | 代号 | 默认策略 | 允许工具 | 禁止 |
|------|------|----------|----------|------|
| 首答/审阅/确认轮 **发言前** | EX-01 / J-06 | **只读** | 读文件、检索记忆、读 MCP resource、只读计算 | 写盘、改代码、高危终端 |
| 工人/评议 **发言后**（本轮消息已 PROTO 入库） | EX-02 前半 | 仍默认只读 | 同上 + 可选静态检查 | 正式工作区写 |
| **评议通过后** 或持有写授权 | EX-02 / J-07 | 可写 | M10 写文件/终端（高危需确认）→ 回执进总线 | 跳过门禁直接标完成 |
| T2 试跑 | — | 仅沙盒 | 沙盒内执行 | 写正式工作区（DEP-11） |

编排器在调用模型前挂「前钩」、在协议消息落库后挂「后钩」；钩子失败记审计，不默默吞掉。

### 5.4 审阅窗、确认轮与通过路径（已确认规则）

> 本节为门禁权威规则；**禁止**配置「跳过确认轮」。

#### 5.4.1 审阅窗何时打开 / 关闭

- **打开：** 共享稿版本 `V` 发布后（首答入库，或合入/R3 后的新版本）。  
- **关闭**（取最早满足者）：  
  1. **全部有效审阅者**已对 `V` **已读**，且距最后一条有效补丁已过 **补丁静默期**（默认 15s，可配置）；或  
  2. **窗超时**（默认 120s，可配置）且至少 1 名有效审阅者已读；或  
  3. 用户/编排器 **强制提交评判**。  
- **关闭后：** 将待合入队列交给 M6；不得自动写入最终回复槽。

#### 5.4.2 确认轮（+1）何时强制发生

下列任一发生后，**必须**进入确认轮（不可跳过）：

| 触发 | 说明 |
|------|------|
| 评议点合入（含单条无冲突补丁） | 稿版本递增后开确认轮，并计算 ChangedSet |
| 冲突合并写回 | 同上 |
| R3 微调写回 | 同上 |
| R1 关闭（重交块被点合入） | 同上 |

> **注意：** 若静默检查无问题、从未合入任何补丁，则 **不开确认轮**，直接等待 **评议通过**（路径·静默通过）。

#### 5.4.3 两条业务路径（替代旧称「路径 A/B」）

> 旧文档中的「路径 A/B」易误解，废止该叫法。以下为权威名称。

**路径·静默通过**

```
用户提问 → 工人首答 → 工人静默检查（首答回喂自身）
  → 无实质问题（可已读/沉默）
  → 【须】评议点「评议通过」一次
  → 写入最终回复；允许执行/交付
```

**路径·补丁确认**

```
用户提问 → 工人首答 → 静默检查或审阅发现实质问题
  → 实质 PATCH → 评议点合入 → 确认轮（仅可改 ChangedSet）
  → 若确认轮仍有实质补丁 → 再合入 → 再确认轮（封顶后升用户）
  → 确认轮已读齐且无有效补丁
  → 【须】评议点「评议通过」一次
  → 写入最终回复；允许执行/交付
```

**共同点：** 无论哪条路径，**都需要评议点一次「评议通过」** 才能最终回复/执行。  
**「轮次通过」≠「评议通过」：** 静默检查通过、确认轮沉默等只表示该轮角色收敛，不能代替评议通过。

#### 5.4.3b 「Pass / 通过」命令对照（消除歧义）

| 口语/旧称 | 权威事件或命令 | 角色 | 是否终局门禁 |
|-----------|----------------|------|--------------|
| 静默检查通过 | `SilentCheckPass` | 工人 | 否 |
| 已读 / 沉默同意 | `Read` + 无有效补丁 | 审阅者 | 否 |
| 合入 | `AcceptPatch` | 评议 | 否 |
| 确认轮沉默 | 确认窗关闭条件满足 | 审阅者 | 否 |
| **评议通过** / 旧称 FinalPass / Pass | **`JudgeApprove`** | 仅评议或降级 A 用户 | **是** |
| 裸「通过」「Pass」无类型 | **禁止** | — | 拒收或要求重发 |

#### 5.4.4 有效审阅者为空时

P0 默认工人即为审阅者。若极端为空，等待评议通过前以用户已读替代确认轮沉默；UI 提示。

#### 5.4.5 工人静默检查与自审（已确认）

- 首答生成后，**必须**将首答再输入工人模型做静默检查。  
- 工人可对自身输出打实质 PATCH（经评议合入）。  
- 工人 **不可以** 任评议，也 **不可以** 点评议通过。  

#### 5.4.6 确认轮 ChangedSet（仅允许改变动块）

**ChangedSet：** 触发本确认轮的写稿动作涉及的全部 `blockId`。  

| 规则 | 说明 |
|------|------|
| 允许 PATCH | `target ∈ ChangedSet` 的实质补丁 |
| 拒绝 PATCH | `target ∉ ChangedSet`（错误：非本轮变动块） |
| 已读 | 仍须对整版当前稿已读 |
| 干净出口 | 无有效补丁且已读齐 → 等待评议通过（**不**自动 Final） |
| 再循环 | 确认轮合入新补丁 → 新 ChangedSet → 新确认轮（受封顶） |
| **全篇打回例外** | 仅当 **评议模型或用户** 发出 **R2(A)**（方向打回、旧稿作废）时，才可跳出「只改变动块」；R2 后走新首答，不在本确认轮内「借机改未变动块」 |

**例：**  
合入只改 `B12` → 确认轮只能再打 `B12`；打 `B03` 拒收。  
若确认轮又合入对 `B12` 的补丁 → 下一确认轮 `ChangedSet={B12}`（或含该次写稿触及的其它块），仍不可借机改未变动块。  
若评议/用户选择 **R2 全篇打回** → 旧稿作废，重新首答；此时不再受上一确认轮 ChangedSet 约束。

### 5.4.7 私有思考区、白板与房间空闲

- 每模型可有私有思考区；自然语言草稿可先落私有区；**他模不可见**。  
- **模型间只能通过白板交流**（共享稿+事件总线）；禁止共享或读取他模思维/私有记忆。  
- 进入白板的消息须结构化（已读/PATCH/弃权/裁定等）；协议归一化负责把模型输出变成结构消息。  
- **用户未提问：房间空闲**；提问后才启动工人/评议流程。

### 5.5 并行首答如何定基准

1. 竞选窗内多人认领首答 → 允许并行生成多份候选稿；  
2. **选定权：** 用户指定 > 评判指定 > 先完成且通过基础校验者；  
3. 未选中稿标记「未采用」，不进入共享稿权威链。  

### 5.6 职责竞选窗与无人认领

| 项 | 规则（P0） |
|----|------------|
| 竞选窗时长 | 默认 60s，可配置 |
| 用户指定优先 | 用户可直接指定首答/审阅/评判，跳过或缩短竞选 |
| 无人认领首答 | 提示用户指定；超时未指定 → 房间停在「待首答」，不空跑 |
| 无人认领评判 | 多模型：提示指定非首答模型；单模型：降级 A（用户评判） |
| 无人认领审阅 | 回退为「除评判外全体（含首答）」自动成为有效审阅者 |

### 5.7 Agent Worker 与 Prompt 编排（P0）

> 覆盖能力项 CH 主循环、OR 编排；tasks 包 **T-AGENT**。

**职责：** 在用户提问后，由编排器按角色向模型投递 Prompt，驱动首答 / 静默检查 / 审阅响应 / 确认轮响应；**评议 Prompt 单独组装，不含过程闲聊**。

| 步骤 | 角色 | Prompt 输入（最小集） | 期望输出（经 PROTO） |
|------|------|----------------------|----------------------|
| W1 首答 | 工人 | 用户原话 + 房间规则摘要 | 正文 → M4 切块入库 |
| W2 静默检查 | 工人 | 原话 + 刚产出的首答全文 | `SilentCheckPass` 或实质 PATCH |
| W3 审阅响应 | 工人（P0） | 原话 + 当前稿 + ChangedSet（若确认轮） | 已读 / 弃权 / PATCH |
| W4 确认轮响应 | 工人 | 同 W3，且系统提示强调仅可改 ChangedSet | 已读 / PATCH（范围受限） |
| J1 评议 | 评议/用户 | 原话 + 当前稿 + 待合入队列 + 开打回 + 规则 | 合入/合并/R1/R2/R3/`JudgeApprove` |

**硬约束：**  
- 未提问不调用 W1–W4 / J1。  
- 工人链路与评议链路 **不得共用** 对方私有思考区。  
- 工人输出不得直接变成 `JudgeApprove`。  
- P0 默认单工人；多审阅者非必做。

### 5.8 输出协议归一化（P0）

> 覆盖功能清单 B-08、纪律 DIS-01/02/11；tasks 包 **T-PROTO**。

### 模块 M4：首答与区块化共享稿

**做什么：** 产出带区块 ID 的权威共享稿；维护版本号。

**合入后 blockId 稳定性（P0）：**  
- 未改动的块：**保持同一 `blockId`**。

1. 若可检测为 MD → 用标题/空行/fence/列表规则。  
2. 否则：按空行分段；单段过长（默认 >800 字或 >40 行）再按句号/换行硬切；每段一个 `blockId`。  
3. 无明显分段的长文：固定窗口切块（默认 500 字，边界向近空白回退）。

#### 6.1 琐碎 vs 实质：判定责任与金样例

**判定责任（显式）：**

1. **第一道：规则引擎（本地，P0 必做）** — 净变更、是否缺 claim/target、是否勾选实质类别、是否匹配禁发模式、全文重写检测。  
2. **第二道：评判可撤销（P0）** — 将已入队贴标为「无效琐碎」并移出队列（不开启互辩）。

   - 权限与 `JudgeApprove` 同属评议权集合。  
3. **可选第三道：模型分类器（P2）** — 辅助标记；不能单独拥有最终拒收权替代规则+评判。

##### 6.1.0 静默期 / 打断 / 澄清计时（状态）

ReviewOpen / ConfirmOpen

##### 6.1.1 净变更计量（TRIV-5 / CH-20）

对某 PATCH，取目标块原文 `old` 与 `replace`（若为 diff 则先还原为新文本）计算 **净变更**：

| 文本类型 | 计量单位 | 算法（P0） |
|----------|----------|------------|
| 中文为主 | **字** | 去除空白后，按 Unicode 码点计「汉字符」；与英文混排时汉字按字、拉丁词按词分别计后相加得到「变更量」 |
| 英文为主 | **词** | 按空白分词；标点单独剥离不计词 |
| 代码块 | **非空行 + 标识符 token** | 先比非空行 diff 行数；再对增删行做简单 token 切分（字母数字下划线）；取 `max(非空行变更数, token 变更数/4)` 作为变更量 |

**净变更量** = `Levenshtein` 类编辑距离的近似：P0 可用「删除字/词数 + 新增字/词数」（不做最优对齐也可）。  

**TRIV-5 触发：** `净变更量 < 100`（中文用字、英文用词、代码用上表变更量）**且**未声明实质 `category` **且** `claim` 匹配低价值模式（如仅「优化一下」「润色」「改改措辞」）→ `Reject(trivial)`。  

**例外：** 已声明实质类别且 claim 指向致命遗漏/事实错误（SUB-4）→ **不过** TRIV-5，即使 &lt;100。

##### 6.1.2 全文重写检测（M5-8 / CH-22）

在无 `REWRITE` 授权、且非「R2 后新首答写入口」时，下列任一成立则 `Reject(full_rewrite)`：

| 条件 ID | 判定 |
|---------|------|
| RW-1 | `replace` 覆盖目标块后，与 `old` 的相似度 &lt; 30%（按 §6.1.1 单位算 `1 - 净变更/(len(old)+1)`）且净变更量 &gt; 0.7×len(old) |
| RW-2 | 单贴 `replace` 文本长度 &gt; 当前共享稿全文长度的 80%，或显式包含 ≥3 个非 target 块的原文片段 |
| RW-3 | `target` 虽为单块，但 `replace` 内出现其它 `blockId` 标记或整章标题重建（启发式：≥2 个一级标题） |

**合法例外：** R2 后的 `CreateFromFirstAnswer`；用户/评议显式授予本轮 `REWRITE` 令牌（令牌一次性，写入审计）。

**应拒（琐碎）金样例：**

| ID | 例子 | 原因 |
|----|------|------|
| TRIV-1 | 把「很好」改成「非常好」 | 纯形容词 |
| TRIV-2 | 只改标点、错别字润色且不改结论 | 语法润色 |
| TRIV-3 | 增加「建议保存后再运行」且不影响原步骤真伪 | 不重要步骤 |
| TRIV-4 | 删除重复的同一句话步骤、语义不变 | 重复步骤 |
| TRIV-5 | 净变更 &lt;100（按 §6.1.1）且未声明实质类别、claim 只写「优化一下」 | 低价值短改 |

**应过（实质）金样例：**

| ID | 例子 | 原因 |
|----|------|------|
| SUB-1 | 改函数签名/控制流 | 实现关键 |
| SUB-2 | request 方案改为 Playwright（有 claim） | 方案方向 |
| SUB-3 | 指出结论数字与原文不符并改正 | 事实 |
| SUB-4 | claim=「缺错误处理会导致崩溃」+ 补 try/except（可 &lt;100 字） | 致命遗漏 |

#### 6.3 冲突「不兼容」判定（M6-4）

同 `target` 存在 ≥2 条有效补丁时：

**步骤 1 — 自动分类**

| 结果 | 条件 |
|------|------|
| **兼容可叠** | 均为 `diff` 且改动行区间不重叠；或一贴只改文案、一贴只改同块内另一互不覆盖片段（区间无交） |
| **不兼容** | 均为整块 `replace` 且归一化文本不等；或 diff 行区间相交；或一对 replace/diff 作用于同一行集 |
| **待裁定** | 自动分类置信不足（如复杂 diff 解析失败） |

**步骤 2 — 处置**

- **兼容可叠：** 评议仍须 **点一次合入**（可一键「按序叠合」）；系统生成合并预览，写入 `MergeRecord.mode=stack`。  
- **不兼容：** **禁止**自动互辩；进入合并台：评议（或用户）从候选中选一、或手写新块文本；`MergeRecord.mode=choose|rewrite`，必须附 `reason`。  
- **待裁定：** 强制打开合并台（同不兼容），不得静默丢弃任一候选。

**人工裁定入口（P0）：** M2 评判台「冲突合并」；命令见下。

**合并策略枚举与命令参数（P0）：**

| strategy | 含义 | 必填参数 |
|----------|------|----------|
| `chooseA` | 采用候选补丁 A 全文 | `target`, `patchId`, `reason` |
| `chooseB` | 采用候选 B（或多选一） | `target`, `patchId`, `reason` |
| `concat` | 按序拼接两贴 replace（仅兼容可叠或用户强制） | `target`, `patchIds[]`, `order[]`, `reason` |
| `rewrite` | 评议手写新块文本 | `target`, `newText`, `reason` |

命令：`MergeConflict({ target, strategy, patchId?, patchIds[]?, order[]?, newText?, reason })`。

**审计：** 保留全部候选 patchId + 最终文本 + reason，供回放。

**R1 重交责任人（P0）：**  
1. **默认强制原作者**：打回块上的 `assigneeAgentId` = 被打回内容的原写入 Agent（首答作者或该块最近合入补丁作者）。  
2. 原作者不可用（离线/禁用）→ 竞选窗重开 **仅针对重交**，或用户指定工人。  
3. 重交内容仍须 **评议点合入** 才关闭 R1。

4. **调用：** 经 §5.3.2 钩子与权限门控；参数 schema 校验。  
5. **回执：** `ToolReceipt` 进总线。  
6. **停用/断开：** 房间结束或用户禁用 → 优雅 shutdown；超时强制杀子进程。  

**终端白名单 / 超时杀进程 / 输出截断（P1a）：**  
- 白名单：可配置可执行文件名或路径前缀（默认仅 `git`, `python`, `node`, `dotnet` 等只读探测类；写操作另需授权）。  
- 超时：默认 30s（可配）；超时 `SIGKILL`/`taskkill` 并回执 `timed_out`。  
- 输出截断：stdout/stderr 各最多 32KB（可配）；超出标记 `truncated=true`。

## 7. 跨模块业务规则（必须遵守）

1. **同意** = 已读 ∧ 无有效补丁；超时 ≠ 同意；弃权 ≠ 同意。  
2. **琐碎**不得进公共流（规则引擎优先）。  
3. **任何**有效实质补丁须 **评议点合入**（含单条无冲突）。  
4. **冲突**默认评判一次合并，不开多轮互辩。  
5. **确认轮：** 有合入则必开确认轮且不可跳过；**无合入的静默通过路径不开确认轮**。确认轮仅允许 ChangedSet 内实质补丁；**唯一跳出**为评议/用户 **R2 全篇打回**。  
6. **打回分档** R1 / R2(A) / R3；R1 关闭=重交后点合入。  
7. **评议**不参与讨论，直读用户原话。  
8. **工人模型 ≠ 评议模型**；单模型 → 用户代评议。  
9. **工人可静默检查/自审补丁**，但不可评议通过。  
10. **模型间只经白板交流**；私有思考区互不可见。  
11. **两路径均须评议点一次「评议通过」** 才最终回复/可执行。  
12. **用户未提问则房间空闲**。  
13. **Windows 本地**；远端服务器改文件非本期。
